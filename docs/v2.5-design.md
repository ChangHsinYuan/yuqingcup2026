# Vidance v2.5 设计文档 — 多入口架构与 H3 引擎接入

> 总览与 v0-v4 路线见 [roadmap.md](./roadmap.md)，v2 长视频见 [v2-design.md](./v2-design.md)
>
> **状态：✅ 已完成**（2026-09-11 端到端验证通过，13 个分镜脚本 / 32 镜 / ~96s 成片）
>
> **使用指南**：见 [usage.md](./usage.md)

## 1. 概述

### 1.1 v2 遗留问题

v0-v2 的架构是一条单线性流水线：

```
概念 → LLM编剧 → 角色锚(FLUX→3DGS) → 逐镜(Wan I2V + TTS) → 审片 → 后处理
```

这条线有三个结构性限制：

1. **单入口单引擎**：只能从一句概念出发，走 LLM 编剧 → Wan 生成。无法用预写脚本、无法选其他视频引擎。
2. **后处理与流水线耦合**：RIFE/LUT/BGM/STT 代码内嵌在 `Pipeline` 类中（5 个私有方法 ~210 行），custom 脚本无法复用。
3. **单角色锚**：v1 的角色一致性依赖 FLUX 生图 → 3DGS 重建，只能锁定一个角色，且 3DGS 质量是瓶颈（character_consistency 2-4/10）。

### 1.2 v2.5 目标

不是在流水线上加功能，而是**重构入口和引擎层**：

- **多入口**：统一 CLI `vidance.py`，三个子命令 `auto`/`custom`/`quick` 路由到不同生成策略
- **新引擎**：接入 MiniMax-H3 ref2va（参考图条件视频生成 + 原生音频），替代 FLUX+Wan 两步流程
- **后处理模块化**：抽出 `PostProcessor` 类，auto 和 custom 共享 RIFE/LUT/BGM/STT
- **多角色**：custom 模式通过 H3 参考图注入支持多角色（最多 10 张参考图）

### 1.3 v2.5 范围

| 做 | 不做（留给后续版本） |
|----|---------------------|
| 统一 CLI 入口（auto/custom/quick） | 异步任务队列（v4） |
| H3 ref2va 引擎接入 + custom 模式 | H3 fl2va 纯文本模式接入（备用） |
| PostProcessor 后处理模块化 | 多引擎自动选择（仍手动指定） |
| 多角色参考图注入 | 多角色交互动作生成（v3+） |
| H3 原生音频保留 | H3 音频质量评估体系 |
| 向后兼容旧入口 | 旧入口废弃 |

### 1.4 核心验证点（含结论）

1. H3 ref2va 能否替代 FLUX T2I + Wan I2V 两步流程 → ✅ 一步生成 1344×768 带音频，角色身份锁定更好
2. H3 参考图注入能否实现多角色一致性 → ✅ 2 角色（豆包+奶蛙）跨 32 镜一致
3. 后处理模块能否被两种模式共享 → ✅ PostProcessor 被 pipeline.py 和 custom_gen.py 共同调用
4. 统一 CLI 能否覆盖所有使用场景 → ✅ auto（概念自动）/ custom（脚本精确控制）/ quick（极速纯 T2V）
5. H3 中文 prompt 直传是否可行 → ✅ Qwen3-VL-32B 原生支持中文，省翻译步骤
6. H3 原生音频质量是否可用 → ✅ 自带音画同步，无需 TTS

## 2. 架构设计

### 2.1 v2 → v2.5 架构演进

```
v2:  单入口 pipeline.py
       concept → LLM编剧 → FLUX角色锚 → Wan I2V(逐镜) → TTS → 审片
       → RIFE → LUT → BGM → STT → 成片
       （后处理 5 个方法内嵌在 Pipeline 类中）

v2.5: 统一入口 vidance.py
       ┌─ auto   → pipeline.py → LLM编剧 → FLUX/Wan → TTS → 审片 ─┐
       ├─ custom → custom_gen.py → 脚本解析 → H3 ref2va(带音频) ──┤→ PostProcessor → 成片
       └─ quick  → pipeline.py → LLM编剧 → Wan T2V → TTS ─────────┘
                              共享: RIFE / LUT / BGM / STT
```

### 2.2 三层架构（v2.5）

```
┌──────────────────────────────────────────────────────────────────┐
│  入口层   vidance.py — 统一 CLI                                  │
│           auto / custom / quick 三个子命令 + 参数路由             │
├──────────────────────────────────────────────────────────────────┤
│  编排层   pipeline.py (auto/quick)    custom_gen.py (custom)     │
│           LLM编剧 + 角色锚 + 逐镜生成   脚本解析 + H3 ref2va     │
│           + TTS + 审片                 + 多角色参考图注入       │
├──────────────────────────────────────────────────────────────────┤
│  后处理   postprocess.py — PostProcessor（共享）                 │
│           RIFE过渡 / LUT调色 / BGM ducking / STT字幕             │
├──────────────────────────────────────────────────────────────────┤
│  引擎层   视频: H3 ref2va (8188, custom)                         │
│           视频: Wan T2V/I2V (8189, auto/quick)                   │
│           角色: FLUX (8192, auto flux模式) + TripoSplat (8192)   │
│           音频: H3原生(custom) / edge-tts + CosyVoice (9880)    │
│           后期: RIFE (GPU2) + ffmpeg LUT/BGM                    │
│           STT: faster-whisper (按需)                             │
│           LLM: USTC API                                          │
└──────────────────────────────────────────────────────────────────┘
```

### 2.3 三种子命令

| 子命令 | 输入 | 引擎 | 编剧 | 角色 | 音频 | 后处理 | 定位 |
|--------|------|------|------|------|------|--------|------|
| `auto` | 一句概念 | Wan T2V/I2V + FLUX | LLM 自动 | 文字→FLUX生图 | TTS | 可选 | 全自动出片 |
| `custom` | 参考图 + 脚本 | H3 ref2va | 预写脚本 | 三视图注入 | H3 原生 | 可选 | 精确控制 |
| `quick` | 一句概念 | Wan T2V | LLM 自动 | 无 | TTS | 无 | 极速出片 |

**设计原则**：
- `auto` = v0-v2 全部能力的入口（向后兼容 pipeline.py）
- `custom` = v2.5 新增的 H3 ref2va 通路（向后兼容 custom_gen.py）
- `quick` = auto 的极简版（关闭全部后处理 + 无角色锚）

### 2.4 参数路由

用 argparse parent parser 实现参数共享：

```
output_parent:  -o/--output          → auto ✓  custom ✓  quick ✓
post_parent:    --no-rife            → auto ✓  custom ✓  quick —
                --lut <style>        → auto ✓  custom ✓  quick —
                --no-color           → auto ✓  custom ✓  quick —
                --bgm <mood>         → auto ✓  custom ✓  quick —
                --no-bgm             → auto ✓  custom ✓  quick —
                --stt                → auto ✓  custom ✓  quick —
auto 专属:      concept (位置参数)    → auto ✓
                --character          → auto ✓
                --character-mode     → auto ✓
                --voice              → auto ✓
custom 专属:    --ref (可重复)       → custom ✓
                --script             → custom ✓
                --ref-image-size     → custom ✓
quick 专属:     concept (位置参数)    → quick ✓
                --voice              → quick ✓
```

## 3. H3 ref2va 引擎接入

### 3.1 为什么选 H3 ref2va

v1-v2 的角色一致性方案是 FLUX 生图 → TripoSplat 3DGS → Wan I2V，有三个问题：
1. 3DGS 重建质量是瓶颈（262K 高斯，像素覆盖 31-35%）
2. 两步流程（先生图再 I2V）累计误差
3. 只能单角色

H3 ref2va 的方案是**每步去噪注入参考图**：
1. 参考图直接作为条件输入，角色身份锁定更可靠
2. 一步生成视频（不需要先 T2I 再 I2V）
3. 支持多张参考图（最多 10 张），天然多角色
4. 自带原生音频（音画同步，不需要 TTS）

### 3.2 H3 工作流

```
LoadImage×N → MiniMaxH3ReferenceToVideo ← prompt(<Picture i> + 中文场景描述)
                     ↑                        ↑
          CLIPLoader(Qwen3-VL-32B)     UNETLoader(ref2va int8)
                     ↓                        ↓
              BasicScheduler ← KSamplerSelect ← RandomNoise
                     ↓
              BasicGuider → SamplerCustomAdvanced → VAEDecode(video)
                                                → VAEDecodeAudio(audio)
                                                → CreateVideo → SaveVideo
```

**关键实现细节**（`comfy_api.py: generate_h3_ref2v()`）：
- 程序化构建 workflow（不用 JSON 模板），参考图数量可变
- Autogrow 输入用 dotted flat keys: `ref_images.ref_image_0`, `ref_images.ref_image_1`
- SaveVideo 输出解析用 `"images"` key（不是 `"video"`，因为复用 image UI channel）
- 帧数自动对齐到 H3 的 17k+5 网格（`align_frame_count`）

### 3.3 H3 prompt 构造

H3 文本编码器 Qwen3-VL-32B 原生支持中文，prompt 直传不翻译：

```
<Picture 1> 是豆包（doubao）：[LLM多模态描述的外貌特征]
<Picture 2> 是奶蛙（naiwa）：[LLM多模态描述的外貌特征]

画面中只能出现这2个角色，外观必须与参考图完全一致，不要创造或添加任何其他角色。

场景：[全局场景设定]。镜头：[分镜描述]
```

- `<Picture i>` 标签引用第 i 张参考图
- 约束指令限定角色数量和外观一致性
- 场景描述拼接全局设定 + 当前镜头描述

### 3.4 角色描述获取

```python
for ref_path in ref_images:
    desc = llm.describe_character(ref_path, name=name)  # 多模态 LLM 看图描述
    # fallback: 超时则用中文名（H3 有参考图注入，描述质量影响不大）
```

### 3.5 ref_image_size

| 模式 | 参考图处理 | 速度 | 质量 |
|------|-----------|------|------|
| `match`（默认） | 缩放到生成分辨率（1344×768） | ~6min/shot | 好 |
| `max` | 保持 2048px | 慢 2-3x | 最佳身份保真 |

## 4. PostProcessor 后处理模块

### 4.1 设计目标

v2 的后处理方法内嵌在 `Pipeline` 类中（`_select_lut`/`_select_bgm`/`_burn_subtitles`/`_run_stt_subtitles`/`_generate_transitions`），custom 模式无法复用。v2.5 抽出为独立 `PostProcessor` 类。

### 4.2 方法清单

| 方法 | 来源 | 作用 |
|------|------|------|
| `generate_transitions(clips, clips_dir, task_id)` | v2 `_generate_transitions` | RIFE 镜头间过渡 |
| `select_lut(concept, script, task_dir, override)` | v2 `_select_lut` | LLM 选/手动指定 LUT |
| `apply_lut(video_path, lut_path)` | **新增**（从 compose 拆出） | 对成品视频施加 LUT 调色 |
| `select_bgm(concept, script, task_dir, duration, override)` | v2 `_select_bgm` | LLM 选/手动指定 BGM |
| `add_bgm(video_path, bgm_path, volume)` | **新增**（从 compose 拆出） | BGM ducking 混音 |
| `burn_subtitles(video_path, srt_path)` | v2 `_burn_subtitles` | 烧录 SRT 字幕 |
| `run_stt(video_path, task_dir)` | v2 `_run_stt_subtitles` | STT 转写 + 烧录字幕 |

### 4.3 两种调用模式

**auto 模式**：后处理在 `compose()` 内部完成（moviepy 拼接 + LUT + 字幕 + BGM 一步到位），Pipeline 只单独调用 `generate_transitions()` 和 `run_stt()`。

**custom 模式**：`concat_videos()` 拼接后，逐步调用：
```
concat_videos() → apply_lut() → add_bgm() → run_stt()
```

`apply_lut()` 和 `add_bgm()` 是 v2.5 新增的独立 ffmpeg 单步操作，不依赖 moviepy。

### 4.4 PostProcessor 初始化

```python
post = PostProcessor(config, llm=llm)
# llm 可选：传则 LLM 自动选 LUT/BGM，不传则用 config 默认值
```

## 5. custom 模式完整流程

```
输入: --ref doubao.jpg --ref naiwa.jpg --script prompt1.txt [--lut ... --bgm ... --stt]

  [1] 解析脚本
      parse_script() → {scene_setting, character_setting, shots[]}
      
  [2] 角色描述（多模态 LLM）
      for each ref_image:
          llm.describe_character(ref, name) → desc
          fallback: 超时用中文名
      
  [3] 逐镜生成（H3 ref2va）
      for each shot:
          构建 prompt: <Picture i> + 约束 + 场景描述
          h3.generate_h3_ref2v(prompt, refs, seed, 1344×768, length, steps)
          → clip_N.mp4（带原生音频）
      
  [4] RIFE 过渡（可选）
      post.generate_transitions(clips) → transition_clips[]
      
  [5] 拼接
      concat_videos(clips, transitions) → final.mp4（保留音频）
      
  [6] LUT 调色（可选）
      post.select_lut() → post.apply_lut()
      
  [7] BGM 配乐（可选）
      post.select_bgm() → post.add_bgm()
      
  [8] STT 字幕（可选）
      post.run_stt() → 烧录字幕
      
  输出: final.mp4 + meta.json
```

## 8. v2.5 vs v0-v2 架构对比

| 维度 | v0-v2 | v2.5 |
|------|-------|------|
| **入口** | 单入口 `pipeline.py` | 统一入口 `vidance.py`（3 子命令） |
| **引擎** | Wan T2V/I2V 单引擎 | Wan（auto/quick）+ H3 ref2va（custom）多引擎 |
| **角色** | 单角色 FLUX→3DGS | 单角色 FLUX→3DGS（auto）/ 多角色参考图注入（custom） |
| **音频** | TTS 双引擎 | TTS（auto/quick）/ H3 原生音频（custom） |
| **后处理** | Pipeline 内嵌 | PostProcessor 独立模块（共享） |
| **编剧** | LLM 自动 | LLM 自动（auto/quick）/ 预写脚本（custom） |
| **代码复用** | Pipeline 类一体 | 入口层 / 编排层 / 后处理层 三层分离 |

## 9. 已知限制

1. **FLUX 8192 已停**：auto 模式 `--character-mode flux/3dgs/auto` 需手动重启 FLUX ComfyUI 实例
2. **H3 显存大**：46G 占满 GPU0，与 FLUX/TripoSplat 不能同卡共存
3. **H3 生成慢**：~6min/shot（match 模式），长片需大量时间
4. **custom 无审片**：auto 模式有逐镜多模态审片，custom 模式跳过（H3 参考图注入质量较稳定）
5. **custom 无 LLM 编剧**：需人工预写分镜脚本，不传概念自动编剧
6. **LLM 多模态不稳定**：角色描述常超时走 fallback，但 H3 参考图注入兜底
7. **后处理参数在 auto 模式走 compose()**：LUT/BGM/字幕在 moviepy 合成时一步完成，不走 PostProcessor 的独立方法（仅 RIFE 和 STT 走 PostProcessor）
8. **quick 模式无后处理参数**：quick 子命令不继承 post_parent parser，无法加 `--lut`/`--bgm` 等
